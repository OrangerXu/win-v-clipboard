# 测试

## 无界面检查

```bash
npm run check
npm test
npm run build:native
```

原生代码使用 `-Wall -Wextra -Werror` 编译。安装模板测试覆盖自启动默认关闭、带空格/引号路径、路径校验和未定义模板字段。

## 真实桌面回归

在 Ubuntu GNOME **X11** 图形会话中运行。额外依赖：

```bash
sudo apt-get install python3-gi gir1.2-gtk-3.0 gnome-terminal x11-utils
npm run build:native
npm run test:e2e
```

测试会打开临时 GTK 编辑器和 GNOME Terminal，改变前台焦点并注入粘贴按键。运行时请勿操作键盘鼠标。先暂停其他剪贴板管理器，包括本应用的生产实例，避免它们收集合成测试内容。推荐使用独立测试桌面会话。

测试使用临时用户数据目录，不修改生产历史文件；结束时尝试恢复启动前可读取的系统剪贴板格式。某些不可读取的格式不能保证恢复，因此不要在剪贴板保存了未备份的重要内容时执行。

覆盖：

1. 确认测试实例未注册 Ctrl+V 或 Ctrl+Shift+V 全局快捷键。
2. 准备一条历史记录，再把系统剪贴板换成别的文本。
3. GTK 编辑器预置“左右”，把光标放在两字之间，通过第二实例唤起面板并点击旧记录。
4. 读取编辑器真实内容，检查英文、中文、首尾空格、多行文本是否准确插入。
5. 在真实 GNOME Terminal 的隔离 PTY 中检查手动和面板点击粘贴的字节；不执行 shell 命令，且不额外发送 Enter。
6. 检查已销毁的窗口目标会返回非零错误，拒绝向其他窗口注入。

日志中出现 `REGRESSION_PASS` 且进程退出码为 0 表示整套通过。只看到 `injected` 并不证明目标应用实际接收了文本。

2026-09-08 的本机修复验证连续三轮通过上述真实桌面测试。该结果不替代在其他桌面环境、Wayland 或自定义终端配置上的测试。
