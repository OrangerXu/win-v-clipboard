# 架构与维护要点

应用由 Electron 主进程、沙箱化渲染器和一个 X11 原生助手组成。渲染器只通过 `preload.cjs` 暴露的窄 IPC 接口读写状态，不直接调用系统命令。

## 自动粘贴顺序

```text
目标输入窗口
  → 系统 Win+V 调用 linux-paste --launch
  → 记录原窗口 XID，传给 Electron 常驻实例
  → 居中显示历史面板
  → 用户点击记录，等待系统剪贴板写入完成
  → 隐藏面板
  → 原生助手激活原窗口并确认输入焦点
  → 等待修饰键释放，按窗口类型发送粘贴组合键
```

不要把“启动了注入进程”当成“粘贴完成”。主进程需等待助手退出；测试还必须读取目标应用的实际内容。

## 关键约束

- Electron 44 的本项目剪贴板调用采用异步接口，写入后要 `await`。
- 沙箱窗口使用 CommonJS 的 `preload.cjs`；保持 `contextIsolation` 和 `sandbox` 开启。
- 第二实例通过 `requestSingleInstanceLock` 的附加数据传递目标窗口。
- 面板已经可见时不要把它自己记成粘贴目标；目标窗口失效时不能随便向当前前台发送按键。
- 使用 EWMH 激活窗口，确认 `_NET_ACTIVE_WINDOW` 和输入焦点后才发送 XTest 按键。
- 不注册 Ctrl+V / Ctrl+Shift+V，不强制释放用户物理按键，不额外发送 Enter。
- 常驻实例必须运行在稳定目录中。重复启动不能清理它仍在使用的资源。
- 历史最多 25 条，单条文本/图片限制为 4 MiB；监听轮询间隔为 650 ms。

## 终端识别

原生助手按 X11 `WM_CLASS` 识别终端。已识别的常见终端使用 Ctrl+Shift+V，xterm/rxvt 类使用 Shift+Insert，其他窗口使用 Ctrl+V。当前仅 GNOME Terminal 完成真实 PTY 回归；列表中的其他终端和用户自定义按键需要另外验证。

内嵌终端可能与所属编辑器共享窗口类，无法仅凭 `WM_CLASS` 区分。若要扩展，应增加可配置策略及对应测试，不要通过抢占系统粘贴快捷键解决。
